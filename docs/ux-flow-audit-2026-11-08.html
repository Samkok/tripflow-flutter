VoyZa UX Flow Audit

What the app asks a traveller to learn, drawn from the navigation code, and the eleven places where it asks for the same thing twice.

Read from the codebase on 8 November 2026 (main at 008976f plus the ended-trip work). Nothing here was measured on a device; tap counts are the shortest path the code allows.

1. The shape of the app

Three tabs. The Trips tab lists trips and opens a trip's page. The Map tab shows one trip at a time, the "active" one, with the plan sheet docked underneath and most editing in sheets over the map. Settings holds account, subscription and preferences.

4. What to simplify, in order

Ranked by how much a traveller's week changes against how much code moves. The first three are structural; the rest are afternoons.

1. One itinerary list, not two

High impactLarge change

Keep the trip page as the place to plan (full-height list, bulk edits, dates, buddies, export) and make the map's plan sheet a thin companion: today's stops in route order, the Not visited and Unscheduled pills as links to the trip page, and nothing that edits structure. Share one card widget and one Options menu between them so an action always looks the same.

Removes: a second selection mode, a second Unscheduled section, a second Not visited section, the Selected/All tab bar, two sort toggles.

2. Retire "Activate" as a concept

High impactMedium change

Opening a trip's map should make it the one on the map; nothing needs a Deactivate button. The Trips tab shows an "On the map" mark on that card. Internally the active-trip id stays; only the three controls go, and with them the write-access checks that key off a trip the user never consciously "activated".

3. One way to add a place

High impactMedium change

A single search sheet, opened from the map's search field and the trip page's + alike, with three tabs inside: Search, Nearby (the long-press picker's content), Paste a link. The day is pre-filled from where it was opened, so the date confirmation disappears for the common case. The loose-place "Add to trip" stays, since it is a different starting point.

4. One planning verb

Medium impactMedium change

"Plan" with two scopes, this day or the whole trip. Re-optimize, Auto-plan, "Put all on one day" and the reschedule-on-date-change prompt become modes of it, in one sheet, with one progress indicator and one undo.

5. A shorter first trip

Medium impactSmall change

Create a trip on one screen: name and country, dates optional with "No dates yet" as the default, buddies invited afterwards from the trip page. Eight taps become three, and a new user meets the undated-trip model (Day 1, Day 2…) without being asked about dates first.

6. A place sheet with a top and a rest

Medium impactSmall change

Sixteen actions read as a settings page. Keep Done, Skip, Route and Schedule at the top; fold Tag, Accommodation, Stay duration and Floor into one "Details" row that expands; collapse Photos and Hours by default. The Options menu on the card then needs only the actions the sheet's top row lacks.

7. One home for the ended trip's leftovers

Medium impactSmall change

They currently have four entrances (pill, list section with switch, Jump-sheet row, trip page panel). Keep the list section as the home and the Jump-sheet row as the map preview; drop the header pill, and make the trip page panel link to the same review sheet rather than repeat the cards.

8. Three map buttons, not five

Low impactSmall change

My location, Fit, Share. "Toggle place names" and "Clear route" move into the map's settings (the tune icon already exists in the plan sheet header). The pulsing Share glow then has less to compete with.

9. One subscription surface

Low impactSmall change

Settings shows "Free Trial" and "Subscription" as separate sections above a separate management screen and the paywall. One "VoyZa Pro" row that opens one screen, which states the trial, the plan and the next charge, and offers upgrade or manage.

10. Count the first-session prompts

Unknown impactNeeds a device run

The code can show up to seven interruptions before a first place is saved: onboarding, analytics consent, ads measurement consent, the iOS tracking prompt, sign-up required, the referral prompt and the paywall. Which of them actually fire, and in what order, depends on flags I cannot read from code alone. This one wants a recording of a fresh install.

11. Day navigation: pick two

Low impactSmall change

◀ ▶ for the next day and the Jump sheet for any day cover every case. The plan sheet's All tab and the Entire-trip legend answer the same "show me everything" question; keep Entire trip on the map and drop the All tab from the sheet once the trip page is the full list.

5. How this was produced, and what it cannot see

The flow map comes from the navigation calls in the code: every push, bottom sheet and dialog, which screen owns it, and which tap reaches it. The counts are of code paths, not of what any traveller did.

Two things no reading of the code can tell: how the screens look at a glance (density, hierarchy, what the eye lands on) and how long each path feels. For the first, VoyZa's screens can be rendered to pictures from a throwaway widget test with the real fonts, which has worked for the Auto-plan sheet and single widgets; the map tiles themselves stay blank in that method. For the second, a recording of a real session on the phone is the only honest source.

Suggested next step: run the three structural changes past one real trip you have planned, and render the proposed single place sheet and single search sheet as pictures before building them.
